A safer CI/CD pipeline with GitHub Actions

A useful pipeline should give fast feedback on every change and make releases repeatable. Keep the first workflow small: install the locked dependencies, run the project’s tests, and make the result a required pull-request check.

Start with a minimal pull-request check

For a Node project with a committed package-lock.json and an npm test script, add .github/workflows/ci.yml:

name: CI

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm test

Use a tested, supported Node version that matches your application instead of copying the example blindly. Pin third-party actions to reviewed full commit SHAs where your organization requires immutable workflow dependencies. Configure branch protection so changes cannot merge until required checks pass.

Reduce pipeline authority

The top-level contents: read permission is a least-privilege starting point for a test-only workflow. Grant write permissions only to the specific job that needs them. Do not expose deployment secrets to pull requests from forks. Treat action versions, scripts, and artifacts from an untrusted change as untrusted too.

Make a release traceable

Build once and promote the same artifact between environments rather than rebuilding different code for each stage. Use protected GitHub environments for deployment credentials and approval gates. Prefer short-lived, federated cloud credentials over long-lived cloud keys when your provider supports them. Record the commit, artifact digest, and deployment result so a release can be traced and rolled back.

Keep the workflow maintainable

Cache dependencies for speed, but keep lockfiles authoritative. Add lint, type checks, security scanning, and integration tests as the project needs them; make each step report actionable errors. Review workflow changes like application code and periodically update pinned actions through a controlled process.
